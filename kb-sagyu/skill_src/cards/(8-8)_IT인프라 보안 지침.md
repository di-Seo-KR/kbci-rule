# (8-8) IT인프라 보안 지침 — 요약 카드
- 소관: IT운영부 정보보호팀 / 시행: 2026. 8. 1.(개정-2026-023) / 조문 수: 110개조(6장) / 별표·서식: 0건
- 한 줄 요약: 서버·데이터베이스·네트워크·정보보호시스템·응용프로그램(개발 포함) 5개 영역별로 도입·설치·변경·폐기, 계정·패스워드, 접근권한·접근통제, 원격운영, 로그·모니터링, 백업·장애·패치·취약점 점검의 보안 기준을 정한 기술 지침. 영역마다 같은 틀의 조문이 반복되지만 숫자·예외가 영역별로 조금씩 다르다.

## 1. 핵심 규칙
- 적용 대상: 정보시스템(서버, 네트워크 장비, 정보보호시스템 등) 운영과 응용프로그램 개발·운영을 하는 모든 임직원(외부인력 포함) (제2조). "정보시스템 관리자"는 각 정보시스템을 직접 관리하는 IT업무부서의 장 (제3조제11호).
- 승인권자 구조: 도입계획·설치·반출·폐기·계정 생성/변경/삭제·관리자권한 부여·정책 변경은 **정보시스템 관리자 승인**, 보안성 검토 신청·취약점 점검 보고·반출폐기 통보·이상징후 통보는 **정보보호 관리자**에게 (제4조, 제5조②, 제6조①, 제10조, 제11조①, 제23조, 제28조①, 제31조, 제48조①, 제51조, 제71조①, 제74조, 제80조①).
- 신규 도입 시 보안성 검토: 서버(제5조④, 제6조①), DB(제28조①; 제27조③은 "보안 취약점진단"), 네트워크(제48조①; 제47조③ "보안 취약점진단"), 정보보호시스템(제71조①). 미비점 조치 → 정보시스템 관리자 승인 → 설치·운영.
- 설치 위치: 서버·네트워크 장비·정보보호시스템은 통제구역에 설치 (제6조②, 제48조②, 제71조②). 외부 서비스 웹서버는 독립 설치, 중요 서버는 독립서버, 개발·운영 서버 분리 (제6조③④). 공개서버는 전용서버로 DMZ에 설치 (제24조①). 중요정보 처리 DB·WAS는 DMZ와 분리된 내부 네트워크 (제28조②).
- 소프트웨어 변경·신규 적용은 1주일 이상 테스트 후 운영 적용 (제7조④). 서버·DB·정보보호시스템 변경작업은 『변경관리 운영기준』에 따름 (제9조②, 제30조②, 제73조②).
- 전산원장 변경: 응용프로그램에 의한 변경이 원칙, 변경 전후내용 자동기록·보존, 불가능하면 공식 승인절차에 따른 변경 의뢰, 제3자(감사자 등) 적정성 확인 (제30조③).
- 폐기: 서버는 저장장치 분리 후 물리적 파기 또는 복구 불가능하게 삭제 (제10조②), DB는 초기화 후 복구 불가능하게 폐기 (제31조②), 네트워크·정보보호시스템은 구성정보·설정 포함 데이터 삭제 (제51조②, 제74조②). 반출·폐기 내역은 기록·정보자산 목록 갱신·정보보호 관리자 즉시 통보.
- 계정: 1인 1계정 원칙, 공용계정 금지 (제11조④, 제32조③, 제52조③, 제75조③, 제101조②). 불필요·퇴직·인사변경·계약종료 계정 즉시 삭제 (제11조⑤, 제32조④, 제52조④, 제75조④). 응용프로그램은 90일 이상 미사용 계정 일시 중지 (제101조③). 제3자 접근권한은 정보시스템 관리자 승인 하에 한시적, 사용완료 후 즉시 삭제·비활성화 (제11조⑦, 제32조⑥, 제52조⑥, 제75조⑥).
- 관리자·특수계정: 승인받은 최소 인원, 추측 가능한 식별자(root, admin, administrator 등) 사용 제한 (제12조, 제33조, 제53조, 제76조, 제102조). 서버는 일반 계정 접속 후 사용자 변경으로 관리자 권한 사용 (제12조④).
- 패스워드 작성규칙(전 영역 공통): 영 대문자·소문자·숫자·특수문자 중 2종류 이상 조합 최소 10자리 이상 또는 3종류 이상 조합 최소 8자리 이상; 이전과 동일한 패스워드 금지; 초기 패스워드 사용 전 변경 (제13조, 제34조, 제54조, 제77조, 제103조).
- **패스워드 변경주기가 영역별로 다름**: 서버·DB·네트워크 = 연 1회 이상(2026.8.1. 개정) (제13조⑤, 제34조⑤, 제54조⑤) / 정보보호시스템·응용프로그램 = 최소 3개월마다 (제77조⑤, 제103조⑤).
- 로그인 실패 5회: 서버·정보보호시스템·응용프로그램은 연속 5회 이상 실패 시 일정시간 잠금 (제15조③3호, 제79조③3호, 제92조①2호, 제105조②), DB는 5회 초과 시 접근 차단 (제36조⑤), 네트워크는 5회 초과 시 자동 연결 해제 (제55조⑤).
- 미사용 세션: 서버·DB·네트워크·정보보호시스템 10분 이상 사용 없으면 자동 로그오프 또는 세션 종료 (제15조⑤, 제36조④, 제55조③, 제79조⑤). 응용프로그램은 "일정시간이상"(숫자 없음) (제105조④). 통제구역 외 서버는 10분 이상 자리 비움 시 화면보호기 또는 로그오프 (제15조⑨).
- 인터넷망 경유 접속: 서버 사용자 접속·업무용 응용프로그램 접속 시 ID/PW 외 강화된 인증수단(OTP 등) 제공 (제15조①, 제105조①). 원격 접근은 암호화 통신(SSH 등) (제15조④, 제79조④). 내부망 원격운영은 IP 또는 MAC 기반으로 특정 단말만 (제16조①, 제37조①, 제57조①, 제81조①).
- 로그 보존: 최소 1년 이상 (제17조②, 제38조②, 제58조③, 제82조②, 제106조②). 개인정보처리시스템 계정·권한 변경 기록 5년 (제17조③, 제38조③, 제106조③ "5년 이상"). 전자문서센터 운영 관련 로그 5년 (제17조④). 정보보호시스템 보안정책 승인·등록·변경·삭제 이력 1년 이상 (제80조⑤).
- 모니터링 주기: 서버·DB 접속기록 월 1회 검토 후 정보시스템 관리자 보고 (제18조①, 제39조①), 네트워크는 "정기적으로" (제59조①), 정보보호시스템 로그는 매월 점검 (제82조⑥), 무선 AP 접속 로그 월 1회 이상 (제68조⑦), 응용프로그램 계정·접근권한 "매월 또는 주기적으로" (제104조④). 서버 성능은 일 단위 측정 원칙 (제19조①).
- 백업: 일별·주별·월별 주기 설정(서버) (제20조②), 중요 데이터·백업데이터 원격지 소산 (제20조④, 제41조③), 응용프로그램 수정 시 소스파일 백업 최소 일주일 이상 보관 (제108조②). 세부는 『백업관리 운영기준』 (제20조⑤, 제41조④, 제61조④, 제85조, 제108조③).
- 백신: 자동 업데이트 또는 일 1회 이상 업데이트, 실시간 감시, 매일 예약 점검 (제25조②③). 공개서버 취약점 점검 연 1회 이상 (제24조②6호).
- 암호화 저장 대상(DB): 고유식별정보(주민등록번호·여권번호·운전면허번호·외국인등록번호), 패스워드, 생체인식정보, 계좌번호 또는 신용카드번호, 그 밖에 회사가 중요하다고 판단하는 정보 (제45조①). 패스워드는 일방향 암호화 (제45조③, 제107조②—생체인식정보 포함). 전송 시 SSL 등 (제107조③).
- 암호키: 정보보호 관리자 승인 받아 생성·기록관리, 서비스와 다른 위치 보관·별도 매체 백업, 하드코딩 금지, 복호화 내역 기록, 영구보관 원칙 (제46조).
- 망분리: 내부통신망 연결 업무용 시스템(사용자PC 포함)은 논리적 또는 물리적 망분리 (제66조①). 망간 자료전달은 인가된 보조기억매체나 망 연계시스템, 고유식별정보·비밀번호·생체인식정보는 암호화; 외부 반출 시 상위 관리자가 개인정보 보유 여부 확인 (제67조).
- 네트워크: 본사-지점 등 원격지 연결은 전용회선 또는 VPN, 무선랜 사용 금지 (제56조⑧). 내부 IP는 사설주소체계, IP 할당은 정보시스템 관리자 승인 (제65조). 무선 AP는 정보시스템 관리자 승인 없이 내부망 연결 금지, WPA2(256비트 이상) 이상, SSID 브로드캐스트 금지, AD 계정 발급 계정만 접속 (제68조②⑤).
- 공개 웹 게시: 해당 부점장 사전 승인, 개인정보·대외비 이상 내부정보 포함 금지, 무기명·가명 게시 금지, 게시 담당자 지정 (제24조③).
- 개발: 테스트에 실제 운영 데이터 사용 금지 (제94조①, 제95조①), 테스트 완료 후 계정·데이터 삭제 (제95조③). 이관은 정보시스템 관리자 승인 후, 개발자 이외의 자가 이관, 사전 전체 백업·롤백 방안 (제96조). 변경 요청은 현업부서장 승인 후 정보시스템 담당자에게 (제97조①). 외부 위탁 개발은 보안요구사항을 위탁계약서 또는 SLA문서에 명시 (제90조①). 동일 사용자 동시 접속 불가, 관리자 전용 응용프로그램은 외부 오픈 차단 (제105조⑥⑦).

## 2. 예외·단서·생략·위임·준용
- (테스트 1주일) 긴급한 패치 적용은 예외 (제7조④ 단서).
- (공용계정 금지) 불가피한 경우 정보시스템 관리자 승인 + 승인 목적 내 제한 사용 + 개인별 사용내역 기록·관리 (제11조④, 제32조③, 제52조③, 제75조③). 응용프로그램은 승인 요건 문언 없이 "목적 내 제한 사용·개인별 사용내역 기록" (제101조② 단서).
- (계정 즉시 삭제) 업무상 보존할 필요가 있는 경우 예외 (제11조⑤, 제32조④, 제52조④). 정보보호시스템(제75조④)에는 이 예외가 없음.
- (공용 패스워드 금지) 불가피하면 사전 승인 + 보호대책 (제13조②, 제34조②, 제77조②); 네트워크는 "사용자 그룹을 식별 관리하는 등의 보호대책"(승인 문언 없음) (제54조②); 응용프로그램은 "업무적으로 불가피하게 사용되어야 할 경우는 제외" (제103조②).
- (패스워드 정기 변경) 업무상 변경 불가 시 정보시스템 관리자 승인 받아 관리 (제13조⑤, 제34조⑤, 제77조⑤, 제103조⑤); 네트워크는 승인 + 대상·사유 목록 관리 (제54조⑤).
- (접근권한 검토 대상 선정) 개인정보를 처리하는 서버·개인정보처리시스템(DB)은 모두 포함 (제14조② 단서, 제35조② 단서). 모니터링 대상도 같음 (제18조① 단서, 제39조① 단서, 제109조① 단서).
- (로그인 실패 경고창) 시스템이 기능을 지원하지 않으면 예외처리 가능 (제15조③4호, 제79조③4호). 정보보호시스템은 로그인 보호대책 전체에 대해 기능 미지원 장비 예외 가능 (제79조③ 단서).
- (10분 자동 로그오프) 서버: 개발업무·모니터링 등 운용상 필요 시 예외 (제15조⑤) / DB: 개발 및 서비스운영상 필요 시 예외 가능 (제36조④) / 네트워크: 미지원 시스템 예외, 필요 시 정보시스템 관리자 승인 받은 경우 예외 가능 (제55조③) / 정보보호시스템: 모니터링 등 운용상 필요 시 예외 가능 (제79조⑤) / 응용프로그램: 개발·운영상 필요 인정 시 정보시스템 관리자 승인 받아 예외 (제105조④).
- (로그인 5회 제한) DB는 업무상 필요에 따라 예외 (제36조⑤), 네트워크는 정보시스템 관리자 승인 받아 예외 (제55조⑤).
- (서버 보조기억매체 원칙 금지) 업무 목적상 예외는 정보시스템 관리자 승인 (제15조⑩).
- (인터넷망 원격운영 원칙 금지) 긴급대응·유지보수 등 불가피한 경우 정보시스템 관리자 승인, OTP 등 강화된 인증, 허용기간 한시 부여, VPN 등 전송구간 암호화, 접속 단말 백신·최신 패치, 원격 접속내역 기록 준수 조건으로 허용 (제16조②, 제37조②, 제81조②). 네트워크는 여기에 "원격운영 현황 지속 모니터링" 추가 (제57조②7호).
- (로그 1년) 5만명 이상 정보주체의 개인정보를 처리하거나 고유식별정보 또는 민감정보를 처리하는 개인정보처리시스템은 2년 이상 (제17조②, 제38조②, 제106조②). 네트워크(제58조)·정보보호시스템(제82조)에는 2년 단서 없음.
- (로그 접근권한 최소화) 개인정보 처리서버는 접속기록 위·변조, 도난, 분실 방지 (제17조⑤ 단서).
- (DB 로그 기록) 성능상 문제가 있다고 판단될 경우 제외 (제38조① 단서).
- (인터넷 통한 패치 원칙 금지) 불가피하면 정보시스템 관리자 승인 (제22조②, 제43조②, 제63조②); 정보보호시스템은 정보보호 관리자 검토 + 정보시스템 관리자 승인 (제87조②). 즉시 패치가 어려우면 사유·보완대책 마련 (제22조⑤, 제43조⑤, 제63조⑤, 제87조⑤).
- (취약점 조치) 불가피하게 조치 불가한 취약점은 사유를 명확히 해 정보보호 관리자에게 보고 (제23조③, 제44조③, 제64조③, 제88조③, 제110조③).
- (DMZ 내 주요 정보 저장 금지) 거래 로그 관리 등을 위해 저장하는 경우 암호화 저장 (제24조⑥ 단서). DMZ에 고유식별정보 저장 시 암호화 (제56조⑦).
- (유지보수계약 체결 원칙) 서버는 미체결 시 적합한 사유 기록 관리 (제26조① 단서). 네트워크(제69조①)는 단서 없이 "체결하여야 한다".
- (DB 도입 타당성 분석) 업무특성·정보화 환경에 따라 BMT 실시 가능 (제27조② 단서). 서버 BMT도 "필요 시 … 할 수 있다" (제5조③).
- (DB·WAS 내부망 구성) WAS가 웹서버와 일체형이라 분리가 어려우면 예외 가능 (제28조② 단서).
- (암호키 영구보관) 암호키 유출 등 부득이한 경우 제외; 파기 시 구성정보 초기화 후 파기하고 정보보호 관리자 보고 (제46조⑤).
- (네트워크 장비 설치 결과 보고) 소규모 작업·변경은 "변경신청서" 작성 후 정보시스템 관리자 승인으로 대체 가능 (제48조② 단서).
- (네트워크·정보보호시스템 콘솔 접근 원칙) 운영·모니터링을 위해 담당자 PC를 사용하는 원격접속은 예외 (제55조①, 제79조①).
- (내부 서버의 외부 인터넷 접속 제한) 불가피하면 정보보호 관리자 승인 (제56조⑨).
- (망분리) 전산센터 내 정보처리시스템의 운영·개발·보안 목적 직접 접속 PC는 물리적 분리 (제66조① 단서). 망분리 예외 적용은 **정보보호위원회 승인을 원칙** (제66조②).
- (통제구역 내 무선 네트워크) 원칙적 금지 (제68조①) — 예외 절차는 문언에 없음.
- (정보보호시스템 기본 계정명 변경) 불가피한 경우 예외 (제75조⑦ 단서).
- (개발·운영환경 분리) 개발 환경이 운영환경에 영향을 주지 않도록 보안 대책이 강구된 경우 예외; 분리가 어려우면 상호검토·상급자 모니터링·변경 승인·책임추적성 확보 등 보안대책 (제89조②③).
- (중요 정보 암호화) 인증정보는 일방향 함수로 복호화 방지 (제92조①8호 단서).
- (테스트에 운영 데이터 금지) 불가피한 경우 정보시스템 관리자 승인과 정보보호 관리자 승인 모두 필요, 운영데이터에 준하는 보호조치 (제95조①②). 제94조①은 가공한 운영 데이터 사용은 허용.
- (응용프로그램 변경 승인절차) 정보시스템 관리자 부재 또는 업무시간 종료 후 긴급 상황에서는 승인절차 **생략** 가능, 단 작업내용 기록 + 반드시 사후 승인 (제98조).
- 위임: 변경작업 → 『변경관리 운영기준』 (제9조②, 제30조②, 제73조②) / 백업 세부 → 『백업관리 운영기준』 (제20조⑤, 제41조④, 제61조④, 제85조, 제108조③) / 안전한 프로그래밍 → 행정안전부 『소프트웨어 개발 보안 가이드』 "참고할 수 있다" (제93조②).

## 3. 다른 사규와의 연결
- 이 사규 → 다른 사규
  - 『변경관리 운영기준』, 『백업관리 운영기준』: 사규 92건 목록에 없음(sagyu.py list·where 확인). 사규가 아닌 부서 운영기준으로 보이며 내용은 원문 확인 필요.
  - 정보보호위원회(제66조②): 「정보보호위원회 지침」(3-4) 실재. 다만 같은 지침 제4조 심의·의결사항에 "망분리 예외"가 명시된 호는 없음(제5호 "기타 의장이 필요하다고 정한 사항"에 해당하는지 원문 확인 필요).
  - "정보보호 관리자", "정보보호 담당자": 이 지침에 정의 없음 → 「정보보호관리 지침」(8-7) 제7조(정보보호 관리자) 등에서 확인.
- 다른 사규 → 이 사규
  - 「정보보호규정」(8-3) 제22조②(패스워드), 제23조③(서버), 제24조④(네트워크), 제25조③(DB), 제26조③(정보보호시스템), 제27조③(암호화), 제28조③(암호키), 제30조⑤(응용프로그램)이 세부사항을 이 지침에 위임. 즉 이 지침은 「정보보호규정」의 하위 세부기준.
  - 「공인전자문서센터 운영 규정」(9-3) 제2조③: 센터 정보보호에 관해 정하지 않은 사항은 『정보보호 관리지침』, 『IT인프라 보안지침』, 『물리보안 지침』 준용.
- 기준이 겹치거나 어긋나는 점
  - 패스워드 변경주기: 이 지침 서버·DB·네트워크 "연 1회 이상"(제13조⑤ 등) ↔ 이 지침 정보보호시스템·응용프로그램 "최소 3개월"(제77조⑤, 제103조⑤) ↔ 「정보보호관리 지침」(8-7) 제45조⑤ "최소 3개월마다"(업무용 PC 및 정보시스템) ↔ 「공인전자문서센터 운영 규정」 제29조 "최소 3개월에 1회 이상". 질문 대상 시스템이 무엇인지 먼저 구분해야 한다.
  - 패스워드 작성규칙: 「정보보호관리 지침」 제45조⑦은 [별표 5] 비밀번호 작성규칙 준용, 「개인정보보호 내부 관리계획」(8-11) 제10조도 비밀번호 관리 규정 — 같은 주제 3곳.
  - 접속기록·암호화·접근통제: 「개인정보보호 내부 관리계획」(8-11) 제9조~제14조, 「신용정보관리 지침」(8-6) 제17조·제19조와 주제 중복(개인정보처리시스템은 그쪽 기준도 함께 확인).
  - 통제구역·출입: 「물리보안지침」(8-9)이 구역 정의·출입통제를 정함.

## 4. 별표·서식
- 없음. 본문이 언급하는 "작업 요청서(또는 계정신청서)"(제30조④, 제32조①, 제52조①), "변경신청서"(제48조②), 장애보고서(제21조② 등), 백업관리대장(제20조①4호 등)은 이 지침에 서식으로 첨부되어 있지 않음.

## 5. 약칭·찾는 말
- "회사" = KB신용정보 주식회사 (제1조) / "정보시스템 관리자" = 각 정보시스템을 직접 관리하는 IT업무부서의 장 (제3조제11호) / "사용자" = 임직원(계약직원 포함)·외부인력 등 모든 내·외부자 (제3조제17호) / "이용자" = 대외 서비스를 이용하는 고객 (제3조제16호) / "외부인력" = 용역계약에 따라 개발·유지보수·운영 등을 하는 인력 (제3조제15호) / "강화된 인증수단" = ID/PW 외 추가 인증(OTP 등) (제3조제3호) / "보안성 검토" (제3조제12호) / "생체인식정보" (제3조제18호).
- 서버 담당자·데이터베이스 담당자·네트워크 담당자·정보보호시스템 담당자·정보시스템 담당자 (제4조).
- 찾는 말: 서버 비밀번호 변경주기, 패스워드 자릿수·조합, 공용계정 써도 되나, 로그 보관기간, 접속기록 점검 주기, 망분리 예외, 원격접속·VPN·OTP, 무선랜·와이파이·AP 설치, 운영 데이터로 테스트, 긴급 프로그램 변경(사후 승인), DB 암호화 대상, 암호키 관리, 보안성 검토, 취약점 점검, 서버 폐기·반출, 홈페이지 게시 승인.

## 6. 주의·정비 포인트
- 패스워드 변경주기 불일치: 2026.8.1. 개정으로 서버·DB·네트워크만 "연 1회 이상"으로 바뀌고 정보보호시스템(제77조⑤)·응용프로그램(제103조⑤)은 "최소 3개월"로 남아 있음. 「정보보호관리 지침」 제45조⑤(3개월)와도 어긋남.
- 항 번호 오류: 제12조에 ③ 없음(①②④⑤) / 제61조 셋째 항에 번호 누락 / 제85조 셋째 항이 "①"로 표기 / 제94조가 ①②③ 다음 ⑥ / 제38조 ④·⑤가 한 줄에 붙어 있음.
- 주체 오기: 제75조(정보보호시스템 계정 관리)⑥의 주체가 "데이터베이스 담당자"로 되어 있음. 제58조⑦ "네트워크보안 담당자"는 제4조에 없는 명칭.
- 중복: 제30조⑥과 제31조③이 같은 내용(DB 재구축·폐기 내역 기록·통보). 제5조(서버 도입)와 제6조(서버 도입 및 설치)의 제목·내용 중첩.
- 용어 불일치: 신규 도입 시 서버는 "보안성 검토"(제5조④), DB·네트워크는 "보안 취약점진단"(제27조③, 제47조③).
- 정의되지 않은 용어: 정보보호 관리자, 정보보호 담당자, 통제구역, 개인정보처리시스템, 전산원장, 전자문서센터, 중요 서버.
- 인용 문서 미확인: 『변경관리 운영기준』, 『백업관리 운영기준』이 사규 목록에 없음. 표기도 사규 「」가 아닌 『』.
- 승인권자 불명: 공용 패스워드 "사전에 승인"(제13조②, 제34조②, 제77조②)의 승인권자 미기재. 응용프로그램 공용계정(제101조②)은 다른 영역과 달리 승인 요건 없음.
- 숫자 없는 기준: 응용프로그램 세션 종료 "일정시간이상"(제105조④), 계정 잠금 "일정시간"(제15조③3호 등), 각종 "주기적으로"·"정기적으로".
- 제66조②: 망분리 예외는 "정보보호위원회 승인을 원칙"이나 「정보보호위원회 지침」 제4조 심의·의결사항에 대응 항목이 명시돼 있지 않음.
- 제56조⑧ "무선랜의 사용은 금지"와 제68조(승인 하 무선 AP 허용)의 관계: 제56조⑧은 본사-지점 등 원격지 연결에 한정된 문언으로 읽히나 해석이 갈릴 수 있음.
- 오탈자: 제3조제7호 "서비를", 제38조② "고유식별정도", 제55조⑦ "운영하다", 제68조② "Acess". 제103조⑦은 문자 종류를 3호(영문 대/소문자 26개)로 적어 다른 조(4호)와 다름.
- 부칙 형식: 2024. 3. 1. 부칙은 "① (시행일)", 2026. 8. 1. 부칙은 "제1조(시행일)"로 형식 불일치.
