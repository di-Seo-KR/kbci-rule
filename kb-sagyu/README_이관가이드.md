# 클로드 코드 이관 가이드

이 압축 파일 하나가 클로드 코드용 사규 프로젝트 전체다. 압축을 풀면 바로 쓸 수 있는 상태이며, 별도로 준비할 파일은 없다.

## 0. 시작 전 확인 — 보안

클로드 코드는 회사 PC에서 실행되고 파일은 로컬에 남지만, **Claude가 읽은 파일의 내용은 답변 생성을 위해 Anthropic API로 전송된다.** 사규 원문 92건이 대상이 되므로, 시작 전에 정보보안 부서와 두 가지를 확인하는 것이 안전하다. 하나는 사규 문서의 대외비 등급상 외부 API 전송이 허용되는지, 다른 하나는 사내망에서 Claude Code 설치와 API 통신(프록시)이 가능한지다. 이미 NotebookLM·Gemini에 같은 문서를 올려 쓰고 있으므로 보안 등급 판단은 동일 선상일 가능성이 높다.

## 1. 설치

터미널(명령 프롬프트)에서:

```
npm install -g @anthropic-ai/claude-code
```

Node.js가 없으면 nodejs.org에서 LTS 버전을 먼저 설치한다. 설치 후 아무 폴더에서 `claude`를 실행하면 로그인 안내가 나온다. 지금 Cowork에 쓰는 것과 같은 계정(Pro/Max)으로 로그인하면 된다.

갱신 스크립트용으로 파이썬 패키지 하나를 설치해 둔다(초안 작성·조회에는 없어도 됨):

```
pip install python-docx
```

## 2. 폴더 배치

이 압축을 원하는 위치에 푼다. 예: `D:\사규정비\kb-sagyu\`

```
kb-sagyu/
├── CLAUDE.md            ← 핵심. Claude가 매 세션 자동으로 읽는 지침·기억
├── sources/             ← 사규 원문 92건 (DRM 해제본 반영 완료)
├── references/          ← 분석서 6종
├── data/                ← 원문 텍스트, 목록, 인용관계, 대장
├── drafts/              ← 개정안 산출물 (여비규정 전부개정안 = 표준 사례)
└── scripts/rebuild.py   ← 사규 개정 시 데이터 재생성
```

`CLAUDE.md`가 Cowork의 스킬을 대신한다. 이 파일이 폴더에 있는 한, 어떤 세션을 새로 열어도 답변 원칙·초안 작성 규칙·미해결 쟁점을 기억한 상태로 시작한다. **세션 간 기억이 파일로 지속되는 것**이라서, 규칙을 바꾸고 싶으면 CLAUDE.md를 직접 고치면 된다(Claude에게 "CLAUDE.md에 이 규칙 추가해줘"라고 시켜도 된다).

## 3. 첫 실행과 동작 확인

```
cd D:\사규정비\kb-sagyu
claude
```

확인 질문 세 개를 순서대로 던져본다.

1. "인사규정 고치면 어떤 사규들을 같이 봐야 해?" → 인용관계.csv 기반으로 12건 안팎을 근거와 함께 답하면 정상.
2. "여비규정 제17조 내용 보여줘" → corpus에서 실제 조문(가족여비)을 인용하면 정상.
3. "내부통제규정 개정하려면 이사회 결의 필요해?" → 이사회규정 제9조제1항제3호를 근거로 "필요"라고 답하면 정상.

## 4. 개정안 요청 방법

세 가지만 알려주면 된다: **대상 사규, 정비 범위, 시행 예정일**(미정이면 공란 처리됨).

예시 프롬프트:

> (7-3) 자산관리규정 전부개정안 만들어줘. 범위는 형식 정비(총칙 복원, 표제·부칙·별표 표기)가 기본이고, 내용은 수기 대장을 전자자산대장(ERP) 기준으로 바꾸는 방향만 반영해줘. 시행일은 미정. 산출물은 개정 사유·주요 내용·전문·신구조문대비표 순서로, 워드 파일로.

받으면 확인할 것 두 가지: 신구조문대비표의 "현행" 열이 실제 원문과 같은지 표본으로 몇 개 대조하고, `<확인 요망>` 표시가 붙은 항목(조직명 등)을 소관부서에 확인한다. 완성본은 `drafts/`에 저장하게 하면 이력이 폴더에 쌓인다.

## 5. 사규가 개정됐을 때 (데이터 갱신)

새 원문 docx를 `sources/`에 넣고 구판을 지운 뒤(파일명의 날짜 부분 갱신) 실행:

```
python scripts/rebuild.py
```

corpus·사규목록·인용관계가 재계산된다. 끝에 "사규 92건 / 인용관계 217개" 같은 요약이 나오는데 건수가 예상과 다르면 DRM 파일이 섞였는지 확인한다. 분석서(references)와 대장 목록은 스크립트가 못 고치므로, 통폐합 등으로 구조가 크게 바뀌면 Claude에게 "재분석해서 references 갱신해줘"라고 요청한다.

## 6. 역할 분담 (이관 후)

| 도구 | 용도 |
|---|---|
| **클로드 코드 (이 폴더)** | 일상 사규 질의, 제·개정 초안 + 신구조문대비표, 데이터 갱신 |
| NotebookLM + Gemini | 원문 92건을 소스로 한 빠른 검색·탐색 (초안 작성은 금지 — references/06의 검증 사례 참조) |
| Cowork (웹 Claude) | 대량 재분석, 통폐합 시뮬레이션 등 무거운 작업. kb-sagyu.skill이 같은 지식을 갖고 있음 |

## 7. 참고

- 한전KDN 사규 50건 원본(PDF, 14MB)은 용량 문제로 이 패키지에서 제외했다. 분석 결과는 references/01에 반영되어 있으므로 필수는 아니며, 필요하면 로컬에 `kdn/` 폴더를 만들어 넣으면 된다.
- NotebookLM에 올려둔 구버전 분석서 2종(체계기준·대장 목록)은 이 패키지의 정정본으로 교체할 것. 구버전에는 부칙 꺾쇠 표기 오류가 있다.
