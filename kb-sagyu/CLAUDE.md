# KB신용정보 사규 프로젝트

이 폴더는 KB신용정보(KB국민카드 자회사) 사규 92건의 조회·해석·제개정 초안 작성을 위한 작업 공간이다. 담당자는 경영전략부 서동인.

## 폴더 지도

| 경로 | 내용 |
|---|---|
| `sources/` | **사규 원문 92건(DOCX). 모든 작업의 유일한 진실.** 파일명 `(분류-번호)_사규명_YYMMDD.docx`의 날짜가 최종 개정일 |
| `data/corpus92.json` | 원문 전문 텍스트 (docx 파싱 결과 — 원문 조회는 이 파일을 읽는 게 빠름) |
| `data/사규목록.csv` | 92건 기본 정보 + 진단 플래그(노후도, 편제, 이사회결의 대상 등) |
| `data/인용관계.csv`, `data/graph.json` | 사규 간 인용 217개 (어떤 사규를 고치면 어디가 영향받는지) |
| `data/대장목록.csv` | 대장 53종 + 근거 조문 + 양식 유무 |
| `references/01~06` | 분석서: 체계기준 / 통폐합 / 거버넌스 저촉 / 상호영향 / 대장 / 외부챗봇 검증 |
| `drafts/` | 완성된 개정안 산출물 (여비규정 전부개정안이 표준 사례) |
| `scripts/rebuild.py` | 사규 개정 시 data/ 재생성 (`python scripts/rebuild.py`) |

## 답변 3원칙

1. **근거 조문 없이 말하지 않는다.** 사규 내용은 `(사규명) 제○조제○항`으로 출처를 밝힌다. 확인 안 되면 "확인 필요"라고 말하고 추측하지 않는다. 조문 확인은 `data/corpus92.json`에서 해당 사규 텍스트를 찾아 읽는다.
2. **사실과 판단을 구분한다.** 조문 대조로 확인되는 것과 상법·금융회사지배구조법 해석이 필요한 것을 섞지 않는다. 후자는 법무 검토 필요를 명시한다. 법률 자문이 아니다.
3. **영향 범위를 먼저 본다.** 사규를 고치자는 요청이 오면 `data/인용관계.csv`에서 그 사규를 인용하는 사규부터 찾아 연동 검토 대상을 제시한다. 92건 중 「다른 사규와의 관계」 조문을 둔 사규가 1건뿐이라 문서만 봐서는 관계가 안 보인다.

## 제·개정 초안 작성 규칙 — 가장 중요

이 프로젝트의 주 용도다. **반드시 지킬 것:**

1. **원문 동결.** 초안 작성 전에 `sources/` 또는 `corpus92.json`에서 대상 사규 전문을 읽는다. 실체 조문(지급 기준·금액·절차·요건)은 요청받지 않는 한 한 글자도 바꾸지 않는다. 원문을 읽지 않고 초안을 쓰면 그럴듯한 조문이 창작된다 — 실제 사고 사례가 `references/06_외부챗봇_검증.md`에 있다.
2. **모든 변경은 신구조문대비표에 사유와 함께 기록.** 현행 열은 원문 그대로 옮긴다. 전부개정은 「사규관리규정」 제18조제2항제4호상 대비표 생략이 가능하나 심사 편의용으로 첨부한다.
3. **확인 안 된 것은 바꾸지 않는다.** 조직명 현행화 등 외부 확인이 필요한 변경은 본문에 반영하되 `<확인 요망>` 표시를 남긴다. 다른 사규의 위임 조문을 인용할 때는 그 조문이 실재하는지 corpus에서 확인한다 (예: "인사규정 제8조"는 신원보증 조문이다 — 과거 외부 챗봇이 위임 근거로 오인용).
4. **시행일·문서번호는 공란.** `[시행 2026. ○. ○.] [2026. ○. ○. 개정-2026-0○○]` 형태. 문서번호는 사규관리시스템 채번 사항(「사규관리규정」 제16조제1항).
5. **산출 후 자체 검증:** 조번호 연속성(제1조부터 빠짐없이), 내부 조번호 참조 갱신(조번호가 밀리면 "제○항"·"제○조" 인용도 확인), 표제 붙여쓰기, 사규 「」·법령 『』, 별표 [별표 제N호].
6. **산출물 구성**은 「사규관리규정」 제18조제2항의 입안 요건에 맞춘다: 개정 사유, 주요 내용, 전문, 신구조문대비표. 워드 파일이 기본 납품 형태.

### 형식 기준 (전부 「사규관리규정」이 근거 — 새 기준을 만들지 말 것)

본칙은 총칙·실체·보칙 3부(제9조). 총칙 순서: 목적 → 정의 → 적용범위 → 다른 사규와의 관계. 조는 장 구분과 무관하게 제1조부터 연번, 표제는 조 번호에 붙여 괄호(제14조). 항 ①, 호 1., 목 가.(제14·15조). 별표 [별표 제N호]·서식 [서식 제N호](제11조제3항). **부칙은 `부 칙(YYYY. M. D.)` 괄호 형식 + 조 구분, 시행일 필수**(제17조, 제10조). 꺾쇠 〈〉는 한전KDN 방식이므로 쓰지 않는다. 전부개정 시 종전 부칙 효력 상실(제21조제3항). 표제 표준: 「정의」(용어의 정의 아님), 「적용범위」, 「시행일」(시행일자 아님), 마지막 장은 「보칙」(기타 아님). 재검토기한 조문(3년)을 보칙에 신설하는 것이 정비 방침.

## 자주 쓰는 조회

- 영향도: `data/인용관계.csv`에서 인용되는사규 열로 검색. 피인용 상위: 정관 23, 인사규정 12, 직제규정 11, 직무전결규정 9.
- 이사회 결의 필요 여부: `data/사규목록.csv` 이사회결의대상 열. 근거는 이사회규정 제9조제1항제3호(8건 열거, 자구수정은 제외 단서).
- 원문 조회: `corpus92.json`에서 file 필드로 찾아 text 읽기. docx를 직접 읽어야 하면 `python -c "import docx; ..."` 사용.
- 대장: `data/대장목록.csv` (53종).

## 알려진 미해결 쟁점 (해당 주제가 나오면 미해결임을 알릴 것)

- 이사가 아닌 경영진 협의체(경영협의회 등)에 이사회 결의사항을 위임하는 것의 상법상 허용 여부 — 법무 검토 대기. 이사회규정 제9조제3항의 「이사회내 위원회」는 실제 설치 사규가 없음.
- 경영협의회 부의규정 별표 제6호("기타 대표이사가 필요하다고 인정하는 규정")의 무한정 문언.
- 계약 권한 기준축 3개(자본금 5% / 건당 5천만원 / 재무관리규정 전결범위) 우선순위 부재.
- 문서번호 이원화: 문서관리규정 제8조 vs 사규관리규정 제16조.

## 갱신 절차

사규가 제·개정되면: 새 원문을 `sources/`에 넣고(구판 교체, 파일명 날짜 갱신) `python scripts/rebuild.py` 실행 → corpus·목록·인용관계 재생성. DRM 걸린 파일은 추출이 실패하므로 해제본으로 교체. 대장 목록과 분석서(references)는 스크립트가 못 고치므로, 구조 변화가 크면 전면 재분석을 요청할 것. 이사회규정 제9조제1항제3호가 개정되면 `scripts/rebuild.py`의 BOARD 상수도 수정.
